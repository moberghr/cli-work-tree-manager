Why work

Several agents should make you several times faster.

Without help you get a terminal per agent, no idea which one finished or is stuck on a prompt, diffs nobody read and worktrees nobody removes. work takes that off your hands.

One task, one worktree, one agent

One step makes the branch, the checkout and the Claude session, and starts Claude on what you asked.

One window for all of them

The Inbox lists the sessions that want you: a permission prompt, finished work, a PR to merge or fix.

A day with work

From the first coffee to the last merge.

Morning: see what needs you

The Inbox lists the sessions waiting for you, most urgent first.

  • A session blocked on npm test: Allow or Deny right there.
  • One that finished overnight: open it on its diff.
  • A pull request approved and green: merge it.
  • Today turns yesterday's work into a standup note.

Start something in one step

Press c, pick the project and say what Claude should do.

  • The branch is named from your words: PAY-31 … becomes feat/PAY-31.
  • The worktree is made, your local settings copied in, and Claude starts on your prompt.
  • Or start from a Jira issue, a pull request, or a PR you were asked to review.

Watch them work

Each session has its terminal, its diff, its pull request and its code. Claude runs in a background host, so closing the window or rebooting doesn't stop it, and work attach puts the same session in your own terminal.

Review what changed, not everything again

  • The diff opens on what changed since you last looked.
  • Pick one turn, one commit, or Shift+click any span of them.
  • Comment on a line: Claude gets it on its next turn.
  • Revert a file, tick files viewed, go full screen.

Find your way in the code

The Code tab shows the session's files with the changed ones marked. Ctrl+T searches types and members by name, files and text across all the repos, as in Visual Studio. Open in editor takes you to the same line in VS Code.

Pull requests, handled

  • Ship… pushes, opens the PR and merges it, checking it still has the commits you reviewed.
  • Failing checks and review comments go to the session's Claude, which drafts a reply to each thread.
  • You edit and post the replies. Nothing reaches GitHub without you.
  • When it merges, the session archives itself.

And the timesheet writes itself

The Time tab suggests each day's hours per Jira ticket from what you did: Claude's working time, your commits, the issues you moved, your meetings. Change what you like, then Post to Tempo.

FAQ

Common questions.

Why worktrees?

Each branch gets its own folder, with its own node_modules, build output, dev server and Claude session. Several agents work at once without stepping on each other, and you never stash to switch.

Does closing the app stop my agents?

No. Claude sessions run in a background host. Closing the app, updating it, or restarting the computer doesn't end them; they come back with their conversation.

Can it post on GitHub without me?

No. Claude drafts replies to review comments; they're posted only when you click Post or tell Claude yes in its conversation. Merging happens only from Ship.

What does Archive delete?

Only what can be recreated. The worktree folder is removed when everything in it is pushed or saved; uncommitted files and local settings are saved first, and Restore puts everything back. A worktree with commits not yet in main is kept.

Do I need Claude Code?

It's the default and gets every feature. Another CLI agent runs in the terminal tab and is managed the same way, without the features that read Claude's conversation and hooks.

Is it open source?

Yes, MIT licensed. Issues and pull requests are welcome on GitHub.
