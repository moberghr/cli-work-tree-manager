# Usage (plan limits and tokens)

The top bar's **Usage** meter (`UsageMeter`, left of the Activity dot) shows the window nearest its limit across every agent and account ("Claude wk 18%": `meterView`, `state/usage-view.ts`; amber from 70%, red from 90%; only the percent below 900 px; "Usage" with no reading; the tooltip has the reset and the age). Its panel (`data-popover`): per agent and account each window as a bar with its percent and reset (`resetPhrase`), how old the reading is (over 6 h it says only a running Claude refreshes it), then the tokens work's sessions used today and this week (input · cached · output, `formatTokens`, per model) and the 5 sessions with most this week (a click opens one). `work usage [--json]` prints the same; both formats come from `core/usage/usage.ts` (pure, import-free), `GET /api/usage` (`UsageWire`) serves it and `usage-changed` (SSE) refreshes it; the demo has its own (`demo-usage.ts`).

**Where the limits come from.** Claude Code gives `rate_limits` only to its status line, so full `work web` sets up each agent's readings (`setupAgentUsage`, `core/usage/usage-setup.ts`, over every adapter's `usage.setup?({enabled, lean})` — `enabled` is config `usage.statusLine !== false`; a lean server passes `lean` and Claude's leaves its settings alone). Claude's wraps the user's `statusLine` command (`core/agents/claude/statusline.ts`, `applyStatusLineSetting`, loaded lazily by `claude/usage.ts` so no hook process pays for the settings editor): `statusLine.command` becomes `work hook statusline || (<the user's command>)` (just `work hook statusline` when they had none; `wrapperCommand`, the parenthesis on a line of its own after a `#`), and the original is kept in `~/.work/statusline.json`. The hook always exits 0 and runs the original from that file itself, so the right side runs only when `work` is gone (uninstalled, off PATH) — the user's line still shows. A wrap over a line that is ours re-writes its fallback from the saved original; a line the user set since (`/statusline`) isn't ours, so it is saved fresh with a new fallback. The hook's half — what runs on each refresh: `readSaved`, `originalStatusLine`, `shellFor`, `runStatusLineCommand`, `isOurs` — is `claude/statusline-run.ts`, and the hook itself `claude/statusline-hook.ts` (with `claude/rate-limits.ts`: `parseClaudeRateLimits` and `accountOf`, Claude's account from `CLAUDE_CONFIG_DIR`; `core/usage/` stays agent-neutral). A command that already runs work's hook (`… hook statusline` under any path, with or without its `||` fallback) is taken as ours and never saved as the original — it would run itself; the user's command runs with `WORK_STATUSLINE_NESTED=1`, and the hook run with it records but runs nothing more. **The wrapper stays when work web stops** (a plain CLI call; a missing work web changes nothing about it). To give it back: config `usage.statusLine: false` (applied at the next work web start), or `work usage --restore` now (each adapter's `usage.restore?()`). Settings that an edit leaves as they were aren't written (`applyEdit`: no rewrite, no backup — the file is often synced or in a dotfiles repo). Unwrapping puts the saved original back only when `statusline.json` reads (`readSaved`: an original, or an explicit none); missing or damaged, work's line stays and a warning names the file — dropping it would lose the user's. The saved file is deleted only after the settings were written and a re-read shows the status line is no longer work's. The hook loads no CLI: it records the window, then runs the user's own command as Claude Code would (sh / Git Bash, 5 s cap — on POSIX its own process group, killed whole —, its output passed through, silent on failure: what goes wrong is in the debug log), and exits once stdout is flushed, so nothing the command left behind keeps it alive (the command's exit decides, not its stdout closing: a `cmd &` it left holding stdout would have held the line until the cap). Readings are `~/.work/usage/<agent>-<account>.json` (account = `default`, or a hash of `CLAUDE_CONFIG_DIR` when it isn't `~/.claude`, so several accounts work), stored by `core/usage/usage-store.ts`; within one window (same id and reset time) the higher percent is kept, since an idle Claude's redraw can carry an older figure; a window whose reset has passed reads 0 (`agedWindow`). The adapter part is `usage` (`AgentAdapter.usage`: `AgentUsageSource` — `read()` → `UsageAccount[]` (`core/usage/usage.ts`, the one shape the store, the source and the wire's `UsageAgentWire` share), optional `setup` and `restore`), so another agent adds its own. **Tokens** are counted once per API message id (`ConversationEntry.message`: Claude writes one message over several lines) in the work-time read (`work-time-source.ts`), per local day, so today and the week cost no extra read of the transcripts; they come from the agent's `conversation.usageFiles` (Claude's: each transcript and its `subagents/agent-*.jsonl`, whose tokens count against the plan too), while work time reads `files` alone. A file last written before the week began isn't read. `GET /api/usage` is one shared build, reused 5 s and dropped when a reading changes (`createUsageCache`; `wireUsage`, `usage-routes.ts`, mounts it with the readings folder's watch, as work web does); a failed fetch keeps the panel's old numbers and says so (with none yet, "Usage unavailable: …").
