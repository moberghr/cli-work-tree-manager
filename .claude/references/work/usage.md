# Usage (plan limits and tokens)

The top bar's **Usage** meter (`UsageMeter`, left of the Activity dot) shows the window nearest its limit across every agent and account ("Claude wk 18%": `meterView`, `state/usage-view.ts`; amber from 70%, red from 90%; only the percent below 900 px; "Usage" with no reading; the tooltip has the reset and the age). Its panel (`data-popover`): per agent and account each window as a bar with its percent and reset (`resetPhrase`), how old the reading is (over 6 h it says only a running Claude refreshes it), then the tokens work's sessions used today and this week (input · cached · output, `formatTokens`, per model) and the 5 sessions with most this week (a click opens one). `work usage [--json]` prints the same; both formats come from `core/usage/usage.ts` (pure, import-free), `GET /api/usage` (`UsageWire`) serves it and `usage-changed` (SSE) refreshes it; the demo has its own (`demo-usage.ts`).

**Where the limits come from.** Claude Code gives `rate_limits` only to its status line, so work's settings file for its Claudes (`agents/claude/session-settings.ts`, Attention inbox) sets `statusLine` to `<this work> hook statusline` — for those processes only: `--settings` takes the place of the user's line there, and the user's own settings are never touched. Config `usage.statusLine: false` leaves it out of the file (the user's line shows, no readings). The hook (`claude/statusline-hook.ts`, with `claude/rate-limits.ts`: `parseClaudeRateLimits` and `accountOf`, Claude's account from `CLAUDE_CONFIG_DIR`; `core/usage/` stays agent-neutral) records the window, then runs the line Claude Code would have shown without work's (`userStatusLine`, `claude/statusline-run.ts`): the project's `.claude/settings.local.json`, its `.claude/settings.json`, then the account's own `settings.json`; one that is still work's (an older work web wrapped it: `isOurs`, `… hook statusline` under any path) is the saved original's (`readSaved`, `originalStatusLine`). The user's command runs with `WORK_STATUSLINE_NESTED=1`, and the hook run with it records but runs nothing more. **The wrap of before**: older work webs rewrote the user's `statusLine.command` to `work hook statusline || (<theirs>)` with the original in `~/.work/statusline.json`, so every Claude ran it; work web's start gives it back (`usage.setup` → `unwrapAllStatusLines`, `claude/statusline.ts`, loaded lazily so no hook process pays for the settings editor), as does `work usage --restore` (`usage.restore`). Settings that an edit leaves as they were aren't written (`applyEdit`: no rewrite, no backup — the file is often synced or in a dotfiles repo). Unwrapping puts the saved original back only when `statusline.json` reads (an original, or an explicit none); missing or damaged, work's line stays and a warning names the file — dropping it would lose the user's. The saved file is deleted only after the settings were written and a re-read shows the status line is no longer work's. The hook loads no CLI: it records the window, then runs the user's own command as Claude Code would (sh / Git Bash, 10 s cap (`USER_LINE_TIMEOUT_MS`: a script starting `jq` and `git` took 3.6 s on a busy Windows machine and went blank at 5 s) — on POSIX its own process group, killed whole —, its output passed through, silent on failure: what goes wrong is in the debug log), and exits once stdout is flushed, so nothing the command left behind keeps it alive (the command's exit decides, not its stdout closing: a `cmd &` it left holding stdout would have held the line until the cap). Readings are `~/.work/usage/<agent>-<account>.json` (account = `default`, or a hash of `CLAUDE_CONFIG_DIR` when it isn't `~/.claude`, so several accounts work), stored by `core/usage/usage-store.ts`; within one window (same id and reset time) the higher percent is kept, since an idle Claude's redraw can carry an older figure; a window whose reset has passed reads 0 (`agedWindow`). The adapter part is `usage` (`AgentAdapter.usage`: `AgentUsageSource` — `read()` → `UsageAccount[]` (`core/usage/usage.ts`, the one shape the store, the source and the wire's `UsageAgentWire` share), optional `setup` and `restore`), so another agent adds its own.

**A model's own limit (Fable's)** is in no status line and no rate-limit event; `/usage` shows it ("Current week (Fable)"). work asks Claude Code for it the way Novadeck does (`claude/usage-ask.ts`): a `get_usage` control request (`skip_behaviors: true`) written to `claude -p --input-format stream-json --output-format stream-json --verbose --setting-sources "" --no-session-persistence --strict-mcp-config`, with no prompt, from a neutral folder — no model runs, nothing is spent, it answers in about 1.5 s, signed in as the account's sessions are (no token of ours; `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` taken out, the account's `CLAUDE_CONFIG_DIR` as `accountEnv` gives it, the internal-run marker on). Measured on 2.1.330 (2026-11-21): `rate_limits.model_scoped` lists each model's window (`display_name`, `utilization` 0–100, ISO `resets_at`) → window `seven_day_model_<name>`, "Weekly Fable limit"; `seven_day_opus` / `seven_day_sonnet` where the plan has them. Those windows are `asked`: the status-line hook's next reading keeps them (`recordReading` carries stored `asked` windows it doesn't have), and the next answer — a `full` reading — replaces the whole set, so a window the account lost goes. Undocumented: an answer that doesn't fit records nothing (debug log), the status line's readings stay. Asked at most every 5 minutes per signed-in account (`setUpAccounts`, `isLoggedIn` not false), one account at a time, and not in work web's first minute (`REFRESH_AFTER_START_MS`, `wireUsage`: its start restores sessions, each a Claude Code starting; reported: asking both accounts at once beside a desktop update's restart added to a 19 s stall), by `AgentUsageSource.refresh` (`refreshUsage`, `usage-source.ts`): `GET /api/usage` starts it without waiting (its answer is a reading, so the folder watch announces it — and since the status line writes a reading as a Claude works, an active account is asked about every 5 minutes, an idle one not at all), `work usage` waits for it.

**Tokens** are counted once per API message id (`ConversationEntry.message`: Claude writes one message over several lines) in the work-time read (`work-time-source.ts`), per local day, so today and the week cost no extra read of the transcripts; they come from the agent's `conversation.usageFiles` (Claude's: each transcript and its `subagents/agent-*.jsonl`, whose tokens count against the plan too), while work time reads `files` alone. A file last written before the week began isn't read. `GET /api/usage` is one shared build, reused 5 s and dropped when a reading changes (`createUsageCache`; `wireUsage`, `usage-routes.ts`, mounts it with the readings folder's watch, as work web does); a failed fetch keeps the panel's old numbers and says so (with none yet, "Usage unavailable: …").

**Which account the top bar reads** (reported: after moving every session to a second account and making it the default, the bar still showed the old account's 98%): `meterWindow` reads, for each agent, the account in use — the one new sessions start on (`UsageAccount.isDefault`) — and every account only while none is marked. The panel still lists every account with its windows, so one that is nearly out stays visible there.

**work's own line.** Config `claudeStatusLine: "work"` (Settings → Agents & terminals; asked once in the dashboard's update corner while unset — and only of someone with no status line of their own: `AgentUsageSource.ownStatusLine`, Claude's = a line in any account's settings, `anyOwnStatusLine` → `SettingsWire.ownStatusLine` via `withOwnStatusLine`; theirs stays theirs unless they pick work's in Settings —, `StatusLineAsk`) draws the line in the hook itself (`claude/work-line.ts`): model and context %, the account (`default`, its `claudeAccounts` name, else its folder's; left out with only one account), the folder (`~/…`) and the branch read from `.git/HEAD` (short commit when detached) — no shell, `jq` or `git`, so it costs nothing per refresh. `"own"` or unset: the user's own line, as above. The hook reads config.json as plain JSON (`readLineConfig`; it may not load config.ts). Choosing it puts work's line in the session settings even with `usage.statusLine: false` (`writeSessionSettings`). It shows on the Claudes work starts; your own settings are never changed.
