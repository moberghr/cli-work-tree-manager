# The Ctrl+K assistant

Ctrl+K (or "Ask" in the top bar) opens a right-hand panel with a real agent session — config `assistantAgent` (`assistantAgent()`, Claude Code by default): session id `assistant` in the PTY host, like any worktree's, keeping its conversation (`--continue` in its folder). It starts when you open it: a PTY host restart doesn't restore it (`PtyRegistry.restore` skips it — restored, one opened once ran for good), and idle sleep stops it by the same rules as a session (its panel open is a terminal attached). It runs in `~/.work/assistant/`, which `prepareAssistantDir(agent)` (`core/agents/assistant.ts`) rewrites before each spawn (`assistantSpec`, `pty-pool.ts`): its instructions file (`ASSISTANT_INSTRUCTIONS` as CLAUDE.md for Claude: its role; get data with `work … --json`, ask before changing anything) and, through the adapter's `workspace`, its settings: the pre-allowed read-only commands (`ASSISTANT_ALLOW`) and a turn-start hook (`ASSISTANT_HOOKS` → `work hook assistant-context`; Claude's: `.claude/settings.json`, UserPromptSubmit). While the panel is open the SPA posts the view (`POST /api/assistant/context`: tab, sub-view, session); the server puts it into words (`describeView`, with the session's status, diff, overlaps) and the hook adds it to every prompt for 30 minutes, so "this" and "these" mean what's on screen. The panel stays mounted after the first open; Ctrl+K works from inside a terminal (a capture-phase listener).

§ It runs in the agent's normal permission mode, as every session does. `ASSISTANT_ALLOW` holds only read-only commands, with exact rules for cleanup: a `work cleanup --json` prefix rule would let `--apply` through without asking (tests/core/assistant.test.ts checks work's rules and what Claude was given). The user's own "don't ask again" choices go to the agent's local settings (`.claude/settings.local.json`), which work never writes.
