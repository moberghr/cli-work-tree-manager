# Agents (`core/agents/`: Claude Code today, others later)

work talks to a coding agent through an `AgentAdapter` (`agents/types.ts`); Claude's (`agents/claude/adapter.ts`) is the only one, and a tool with no adapter (`aiCommand: opencode`) gets a plain one (`agentById`) that starts and does nothing else. A session runs the agent it recorded when it was created (`WorktreeSession.agent`; `agentFor(config, session)`), so changing the default never changes what an existing session runs. Only an agent work has an adapter for is recorded (`agentToRecord`, `isKnownAgent`): an unknown command follows `aiCommand` as it is, since its binary alone (`node` of `node my-agent.js`) can't start it again.
- **`launch`** (every agent): `tool(config)` (binary + flags; config `aiCommand` / `aiCommandFlags` when they name it), `canResume(cwd)` (the resume gate — Claude's is `hasClaudeConversation`; a plain agent never resumes), `resumeLaunch(session)`, `cleanEnv(env)` (a parent session's variables). `work tree` / `resume` / `recent`, the pool's spawn spec and the PTY host's resume check (`PtyRegistry` by the spawned tool) ask it; the Ctrl+K assistant is always Claude's (its folder holds Claude settings).
- **`conversation`** (optional): `files(session)` (one file per conversation, a JSON value per line — Claude's transcripts, `agents/claude/files.ts`), `usageFiles?(session)` (the files whose tokens count: the conversations and their subagents'; absent: `files`), `entries(lines)` (its lines as `ConversationEntry { at, role: you|agent|tool|tool-result|other, text, tool?, id?, sidechain?, usage?, model? }`: every line gives at least one, `other` keeps the non-messages because work time measures the gaps between all lines; Claude's mapping is `agents/claude/entries.ts`, the one place work reads Claude's line format), `contextWindow(model, used)`, `read(session, {last})`. Context %, title, work time, the digest, the timeline, catch-up, conversation copies and search, the archive's prompts and transcript copy, a session's activity (`core/sessions/session-activity.ts`: the newest write to its files — Active / Open / Stale, "last active") and turn activity (`lastTurnEntryMs`: a turn's message after the turn ended; entries mark the agent's own lines `meta` and a shell command or task result `turn`) all read through it, and the pure parts (`promptsSince`, `workSteps`, `contextUsageFrom`, `catchUpTimeline`, `messageOf`) take `ConversationEntry[]`. An agent without it gets none of these — never Claude's files read as if they were its (`tests/core/agent-readers.test.ts`).
- **`events`** (optional): work's hooks are in work's own terms — a turn edge (`turn-start`, `turn-end`, `notify`; `SESSION_HOOKS`, `agents/session-hooks.ts`) — given to the processes work starts by `launch.sessionTool` (Claude's: `--settings`, `claude/session-settings.ts`); the adapter takes out of its own settings what older work webs installed there (`removeInstalled`, owners `RETIRED_HOOK_OWNERS`), reads what it sends them (`read(edge, payload)` → the folder and a `StatusEvent`, `core/status/status-event.ts`), and says how notes are handed back (`handOver`). Claude's (`agents/claude/hooks.ts`) maps the edges to UserPromptSubmit / Stop / Notification and keeps the command `work hook <edge>`; another agent's hooks would say `--agent <id>` (`hookAgentArg`; none = Claude). - **`live`** (optional): its running processes as `LiveAgent` (pid, conversation, folder, busy / idle / waiting) — Claude's from `~/.claude/sessions/<pid>.json` (`agents/claude/live.ts`, believed only for a live Claude pid). `liveAgents(table?)` gathers every known agent's; `live-agents.ts` groups them by session (`agentsBySession`, `summarizeAgents`) for the dashboard, the Terminal tab's "running elsewhere", start / send, the PR watch's wake and build-folder clearing.
- **`input`** (every agent): `submit(write, text)` types into its prompt — text, a pause (`SUBMIT_DELAY_MS`), then Enter as `
` apart (Claude reads a burst as a paste; `agents/typing.ts`, a plain agent gets the same) — used by every note pushed into a terminal (`typeAndSubmit`). `permissionDialog` (optional: Claude's `checkDialog` + Enter / Esc, `agents/claude/permission.ts`) is the only way a keystroke answers a permission prompt (`POST …/answer`, `work answer`); an agent without it is answered in its own terminal.
- **`oneShot`** (optional): a text-only run for work's own summaries (checkpoint names, catch-up, archive summaries, the Jira watch's choice, a group's instructions file) — prompt on stdin, answer on stdout, no tools, no MCP servers, a neutral folder, env tagged internal so its hooks don't fire into work. Claude's is `claude -p --tools "" --strict-mcp-config` (`internalClaudeSpawn`; `small` → `CLAUDE_SMALL_MODEL`). `runInternal` (`core/diff/checkpoint-summary.ts`) runs config `internalAgent` (default `claude`), one at a time per **lane** (`InternalLane`, `{lane}` on `runInternal` / `runInternalReadOnly`): `shared` (default) for everything quick — checkpoint names, Catch me up, fork and archive summaries, the Time AI step, the Jira watch, a group's instructions — and `reviews` for the Reviews AI step alone, which can hold its lane for minutes (a checkout run, then the fallback), so nothing else waits behind a review; lanes don't wait on each other, each keeps its timeout and tree-kill (`tests/core/diff/checkpoint-summary.test.ts`); an agent without it writes none and each feature falls back (a size label, no summary). Optional `oneShot.readOnly` (`AgentReadOnly`): the same, but reading a folder — the Reviews AI step's temporary checkout of a PR (`command({cwd})`; `runInternalReadOnly`, `internalCanRead`, `internalReadOnly`) — with what only the agent knows of it: `isSettingsFile(rel)`, the folder's files it would read as its settings, deleted from the checkout first (Claude's `claudeSettingsFile`: `.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json` at any depth, in any case — a case-blind file system opens `.Claude/settings.json`), and `promptLines`, what the prompt says of its tools and instructions files (Claude's `CLAUDE_READ_ONLY_LINES`: Read, Grep and Glob; CLAUDE.md and `.claude/rules`). Claude's (`internalClaudeReadOnlySpawn`): `claude -p --restricted --tools Read,Grep,Glob --setting-sources user --add-dir <cwd> --strict-mcp-config --permission-mode dontAsk` with `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`, measured on Claude Code 2.1.317: `--setting-sources user` keeps the folder's settings and hooks unread but drops its CLAUDE.md too, which `--add-dir` + that variable bring back (CLAUDE.md and `.claude/rules`; a subfolder's CLAUDE.md isn't loaded by itself — the prompt asks it to read them); `--restricted` confines Read/Grep/Glob to the folder (without it a Read elsewhere on disk worked); a CLAUDE.md `@import` of a file outside the folder (`@../x.md`, an absolute path) isn't loaded (measured 2026-11, with and without `--restricted`: Claude Code loads an import from outside the project only once approved in a dialog, which `-p` never shows; one inside the folder is). Those flags were measured on one version, so `readOnly.available()` says whether the installed agent may run it: Claude's (`agents/claude/version.ts`, `claudeReadOnlyAvailable`, loaded lazily) asks `claude --version` (10 s timeout, its process tree killed at it; kept per binary — `binaryStamp`: the real file, links followed, its `installTime` (npm's 1985 mtime read as the agent restarter does) and size — for at most `VERSION_TTL_MS`, 10 min; a binary that can't be stamped and an unknown answer are asked again next time) and needs at least `READ_ONLY_MIN_VERSION` (`internal.ts`, beside the flags: 2.1.317); older, or a version that can't be told, gets no checkout run (`agentInCheckout` → `{skipped, why}`) and the review reads the diff alone, Activity saying why. An agent without it: the diff-only `command` run.
- **`instructionsFile`** (every agent: Claude `CLAUDE.md`; one with no adapter `AGENTS.md`, the convention Codex, Copilot and opencode read): a group's combined file is generated from each repo's file of that name (`group-instructions.ts`, written by `runInternal`, kept as `~/.work/<group>.claude.md`) and copied into each group worktree's root under it, removed with the worktree. **`conversation.restoreDir`** (optional): where an archived conversation goes back so the agent resumes it — Claude's projects folder for the folder it runs in; without it Restore starts fresh and the archive keeps the files. **`workspace`** (optional): a folder work runs it in — the Ctrl+K assistant's — gets its settings through `write(dir, {allow, hooks})`: `AllowRule`s (a command, exact or `prefix`) and `WorkHook`s; Claude's writes `.claude/settings.json` (`Bash(cmd)` / `Bash(cmd:*)`, `agents/claude/workspace.ts`). It returns the files it wrote: the assistant keeps the list (`.work-written.json`) and, when its agent changes, removes what it wrote for the last one (instructions, allow rules, hooks) — only listed files inside the folder, never the user's local settings. Without it only the instructions file is written. **`skills`** (optional): `install({skillsDir})` gives it the SKILL.md folders in `plugins/work-tree/skills` (the Agent Skills format); Claude's registers the `work-tree` plugin marketplace (`agents/claude/skills.ts`). `installSkills` (`core/agents/skills.ts`; `scripts/postinstall.mjs` → `dist/install-skills-bin.js`, or `work install-skills`) does every known agent; a missing local folder is each agent's to judge (Claude's come from its marketplace), and a failed `claude plugin install` is reported with how to do it by hand unless `claude plugin list --json` has it already. The skills speak to any agent (a test keeps "Claude" out of them).
**Lookups and the wire.** `agentOf(session)` is `agentFor(agentSettings(), session)`: `agentSettings()` reads config.json's `aiCommand` / `aiCommandFlags` / `internalAgent` / `assistantAgent` once and again only when the file changes (path, size, mtime), since the lookups run per row of every session list. `registerAgent(adapter)` adds one (returns its removal). The dashboard is told each session's agent as `SessionWire.agent` (`agentWire`: id, name, and `can: { read, hooks, live, answer, accounts }` from which adapter parts exist), and its running processes as `agents` (`claudes` is the same, deprecated, kept one version for `--json` readers). The SPA names it with `agentName` and hides what it can't do with `agentCan` (`state/session-display.ts`): no Allow / Deny without `answer`; a row from an older server reads as Claude with everything. **Readiness proof**: `tests/core/echo-agent.test.ts` registers a made-up agent with its own conversation format, hooks, process list and instructions file, and runs a session on it through the real modules (launch, context, title, activity, work time, timeline, hooks, notes, live processes, the wire, a group's file) with no Claude file anywhere. A new agent (Codex, Copilot) is an adapter in `agents/` plus `registerAgent` (or the built-in table), and that test as its template.

**Accounts** (Claude's: `agents/claude/accounts.ts`, `account-admin.ts`, `account-move.ts`; core sees the optional adapter part `accounts` — `list()`, `defaultName()`, `has(name)`, `current(session)`, `switchFiles(session, to)` (the move, putting back what it moved when it fails), `folders(session)` (where a switch moves conversations) and `admin` (`add`, `setDefault`, `remove(name, usedBy)`, `login(name)` — the agent's own CLI in this terminal, config `aiCommand` respected when it is Claude —, `installSkills(name)`) —, the policy is `core/sessions/account-switch.ts`). Core and commands reach it only through `agentFor(config, session?).accounts`: `history.ts` records an account only for an agent that has accounts (a plain agent's session records none), `worktree.ts` checks a new session's with `accountRefusal` (`has`; an agent without accounts takes only `default`, which a fork passes), `work account` does everything through it; the registry re-exports nothing of Claude's (`tests/architecture/agents.test.ts`), and the dashboard is told `SessionAgentWire.can.accounts` (`agentWire`), which the SPA reads with `agentCan(s, 'accounts')` (`state/accounts.ts`), never the agent's id. An account is a Claude Code config folder (`CLAUDE_CONFIG_DIR`): its own login, settings, transcripts and process files. Config `claudeAccounts: { <name>: <folder> }` and `claudeAccount: <name>` (the default for new sessions, work's own runs and the Ctrl+K assistant); `default` is reserved: `~/.claude`, always there, never the folder of another name; names are plain words, folders absolute (`~` expanded) and never equal to or inside the worktrees root, a repo or `~/.work` (`accountProblem` with `accountForbiddenRoots`). config.ts passes `claudeAccounts` / `claudeAccount` through as written (typed, strings only); the rules are Claude's (`agents/claude/accounts.ts`), applied by its reader over the shared config cache (`configView`, `core/platform/config-cache.ts`: config.json read and parsed again only when it changed, the same cache `agentSettings()` uses) — a bad entry is dropped with a warning said once per change of config.json, not on every lookup; `work account add` (`account-admin.ts`) applies the same rules. (config.ts no longer reports anything, and the status-line hook loads neither it nor report.ts: `tests/architecture/hook-imports.test.ts`.) A session records its account (`WorktreeSession.account`, `SessionWire.account`: absent = `default`; `work tree --account`, New worktree's More options; a fork inherits its parent's). Each launch path gets the folder as an `EnvDelta` (`core/platform/env-delta.ts`) from `accountEnv` — `spawnSpecFor` (the PTY host), `work tree --no-host`, `work resume`, the restarter, a restore — set for a non-default account and **unset for the default one while accounts exist** (a parent shell's own `CLAUDE_CONFIG_DIR` can't send a default session elsewhere), and `agentEnv` (`Entry.env`; `CLAUDE_CONFIG_DIR` is always kept in the restore entry, like `hostEnv`: not a secret). Without accounts nothing is set: today's launch, byte for byte. The resume gate (`hasClaudeConversation`) looks in the session's account folder. **Readers cover every account** (transcripts for status, tokens, work time, search, archive, timeline, catch-up; Claude's `sessions/<pid>.json` for live state and background agents; the activity watch): a session's files are looked up in its own account first, then the others (a switch that failed half-way still finds them). **Hooks and the status line need nothing per account**: they come with each Claude work starts (`--settings`, whatever its `CLAUDE_CONFIG_DIR`), and the status-line hook runs the user's line from that account's own settings. **The skills install is per account folder**: only a folder that exists counts (`setUpAccounts`; installing would make the folder); `work account add` installs the plugin into the new folder after the login (`installClaudeSkillsFor`). The clean-up of what older builds wrote covers every account's `settings.json` (`editSettings(mutate, file?)`; a wrap's saved original was kept per folder, `~/.work/statusline-<account>.json`, the default's `statusline.json`; an account with nothing saved whose settings still run work's line — a settings.json copied from the default's — runs the default account's saved original meanwhile, `originalStatusLine`), and the plugin install runs once per folder; usage readings carry the account's config name and `isDefault`. **The switch** (`work account switch`, ⋯ → Claude account… / ⇧C and the rail menu, `POST /api/sessions/:id/account {to}` → `AccountSwitchWire`: `switched` | `queued` | `recorded`; `GET /api/accounts` → `AccountsWire`): refused — archived session, unknown or not-logged-in account, the one it is on, a Claude running in a terminal outside the host (400/409 with the reason); not running in the host: the conversation folders move and the account is recorded (`recorded`: its next start uses it); idle in the host: halt → move `projects/<encoded cwd>/` for each folder it runs in (transcripts, subagents, memory) into the new account's `projects/`, merging → record → resume in place with the new env (`switched`; the terminal stays attached); working or waiting on you: queued on the restarter (after its turn, its own busy rule; `queued`). A move that fails puts back what it moved, keeps the old account and resumes on it; a rollback that fails too is said with what is stuck where (the answer and the Activity note). **The move never loses a file**: a rename, or across volumes a copy and then a delete; a delete that fails part way (a file in use) copies back into the source what it took, never over what is still there, before the copy goes — should that fail, the copy stays: each file in at least one place, never none (undo goes the same way). **Shared folders**: refused before anything stops (`stays on X: a Claude outside this session runs in <folder>`, `othersRunningIn`) while any live Claude of any account other than this session's own PTY runs in one of the folders it would move; a session on a repo's own checkout (`isOwnCheckout`) moves only its own conversation — per folder, the newest `<id>.jsonl` (the one `--continue` resumes) and its `<id>/` folder (`onlyLatest`) — never the folder's other conversations or `memory/`; a worktree session moves the whole folder. **Queued switches** live in work web's memory (`pendingFor`; a work web restart drops them): `SessionWire.accountPending` names the target while one waits, shown in the header's account chip ("→ work after this turn", the stack chip's style) and the rail tooltip; Claude account… shows it and offers **Cancel the switch** (`DELETE /api/sessions/:id/account`; 409 when none waits or it is being done now; the demo has the route). A switch that fails — one that waited for its turn included — fails its Activity run (`accountSwitchNote`), so the Activity dot lights. An older host (no halt/resume, `agentEnvApplied` missing) is stopped and started instead (`stopped`). **A switch and an agent restart** (`work restart`, Restart agents) never restart one agent twice for one turn (`core/sessions/account-switch-link.ts`, which also carries a turn's end, the sweep and `accountPendingFor` to the switcher in web-server.ts): a switch that runs drops an agent restart waiting for the same turn (`cancelRestart`, said in Activity), and an agent restart asked for while a switch waits or runs is folded into it (`RestarterDeps.foldedInto`: answered as `later`, never queued; a queued one whose turn comes while a switch is due stands down). The refusals before anything stops (archived, no accounts, unknown, not logged in, one already waiting, the same account, running outside) are one pure function, `switchRefusal` (`core/sessions/account-switch-rules.ts`), shared with the demo.
