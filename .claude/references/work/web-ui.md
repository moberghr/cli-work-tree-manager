# The web UI's shared pieces (`src/web/src/ui/`)

**Why.** Each page was styled on its own as it was added. A measurement of the running app found 54 different control shapes (height, corner radius, text size and weight together) from about 40 button-like class names, 12 corner radii and 10 text sizes; the Reviews list was in another typeface, the Time tab's inputs were the browser's own. The look itself was fine where it had been cared for (Sessions, the rail, the Inbox): the unevenness was the problem. So: one scale, one implementation of each control, and pages that compose them (issue #79).

**The scale** is in `styles/tokens.css`, theme-independent: text (`--text-xs` 11 … `--text-title` 18), corners (`--radius-sm` 4, `--radius` 6, `--radius-lg` 8), a control's height (`--control-h-sm` 24, `--control-h` 28, `--control-h-lg` 32), space in steps of 4 (`--space-1` … `--space-8`). They are the values that were already the most used. § A new size is a new token there, argued for; never a number in a page's stylesheet.

**The pieces** (`ui/index.tsx`, styles in `ui/ui.css`):

| Piece | For | Class it renders |
|---|---|---|
| `Button` (`variant`: `primary`, `danger` — the main action when it destroys something, filled red —, `secondary`, `row`, `quiet`, `link`; `danger` on a row's; `size="sm"` for a framed one in a toolbar — 24 px, the height of a Segmented beside it; `icon` for one glyph and no words, a dialog's × — square, the glyph at a title's size; `ref` for a dialog that focuses it; a link's `tone`: `muted` or `inherit` where the blue would shout) | every button; `buttonClass()` for an `<a>` that must look like one | `wd-btn-primary`, `wd-btn-danger`, `wd-btn-secondary`, `wd-row-action`, `wd-topnav-btn`, `wd-link-button`; `wd-btn-sm`, `wd-btn-icon` |
| `Segmented` (`kind="tabs"` when it switches what the view shows: a tablist of tabs, `aria-selected`; `value` null when none is on; per option `muted`, `disabled`, `className`) | a few choices of which one is on (Now / Today, Group: Repo / None, Uncommitted / Since branch, a group's repos) | `wd-segmented`, `wd-segmented-btn(-on, -muted)` |
| `Input`, `TextArea`, `Select` (`compact` in a tight row — a chip row, beside row buttons — 24 px; a `TextArea` with `rows={1}` is a button's height; an `Input` that is `bare` is the search field across the top of a palette, Ctrl+P and code search: no frame, a line under it) | every text box and pick from a list; only checkboxes and radios stay the browser's | `wd-input` (`wd-textarea`, `wd-select`; `wd-input-sm`, `wd-input-bare`) |
| `Tab` | one tab of a strip that switches what is shown below it (the top bar's pages, a session's Terminal / Diff / Code): underlined when on; its height `--tab-h`, the top bar's stretch to the bar | `wd-tab(-on)` |
| `Badge` (`kind`: `count` filled, `tag` outlined, `status` tinted, `letter` a file's A/M/D, square; `tone` by meaning: `neutral`, `accent`, `ok`, `warn`, `danger`, `review`, `merged`; `dashed` for not the real thing yet or no longer — a draft PR, a kept row, an archived session) | a small label in a row; `badgeClass()` for a link (a PR chip) | `wd-badge`, `wd-badge-<kind>`, `wd-badge-<tone>`, `wd-badge-dashed` |
| `Chip` (`remove`: its × with the label of what it takes out; `on` picked, `bad` something wrong; `as="label"` round a checkbox) | a short value you can take out (a scanned folder, a group's repo) or a choice to pick (the new group's repos); 24 px, the height of a compact Select beside it | `wd-chip(-on, -bad)`, `wd-chip-remove` |
| `ToggleChip` (`on`) | a chip you switch on and off, of which several can be on (Start's repos to show); for exactly one of a few, a Segmented | `wd-chip wd-chip-toggle(-on)` |
| `Menu` (`ui/Menu.tsx`; items, rows of swatches, a footer; a `danger` or `separated` item; ↑/↓, Enter, Esc) | a row's right-click menu at the pointer, or a button's (the session header's ⋯, the bulk bar's Snooze); a list dropped under its own button (the version menu, saved prompts) takes its classes and places itself | `wd-row-menu`, `wd-row-menu-item(-danger, -separated)` |
| `PageHeader` (`compact` in a panel or a narrow column: Tasks, a step of the first run, the Reviews list beside a review; always opaque, so a page may keep it at the top) | a page's `h1`, what it counts, its controls on the right | `wd-tab-header(-compact)` |
| `SectionTitle` | the small capitals over a group of rows | `wd-section-title` |
| `ListRow` | a row you click, in a list: a title and a quieter line | `wd-list-row(-active)` |

Each renders the class the pages already used, so markup not yet moved to a component looks the same as markup that is, and a test that finds a control by its class keeps working. A page's own class goes beside the shared one (`className`), for where the piece sits and for tests.

§ **A page places a piece; it never restyles one.** `ui.css` is the only stylesheet that defines the shared classes' look, and it is loaded before the page stylesheets (`main.tsx`): a page's rule for a margin or a width wins. `tests/web/ui.test.ts` fails when a page stylesheet defines a shared class again; when a page rule reaches one through a parent (`.wd-modal button.wd-btn-primary`), a part of one (`.x .wd-tab-header h1`) or every button of a container (`.wd-comment-form button`) and gives it a look — padding, font, colour, background, border, height, filter, opacity — rather than a place; when `ui.css` writes a size as a number of its own; or when the load order changes.

The rules of the second kind that were there when the pieces arrived were listed in that test (`KNOWN`, 31 of them: dialogs' buttons in another blue, Time's view switch, Jira's actions, link buttons in a panel's colour, pages' header backgrounds, smaller titles in a panel…) and each went as its control became a piece or a variant of one; the list is empty. § It stays empty: a control that needs another look is a variant of the piece, in `ui.css` (a `compact` PageHeader, a link Button's `tone`), never a page rule.

§ **WHEN adding or changing a page, use these pieces.** A control none of them covers becomes a new piece here (with its test), not a class in the page's stylesheet.

**Also in `ui.css`:** `button, input, select, textarea { font-family: inherit }` — a control with no rule of its own took the browser's typeface.

- The Diff tab: its toolbar (a group's repos and the scope as `Segmented` tabs, Split / Unified, Changes ▾, Open in browser, Full screen — all 24 px), a file's Revert and Comment on file (row buttons), the comment form and the general note (`TextArea`, `Button`: their main button is the app's accent, no longer `--hunk-fg`), the tree's filter (`Input`). Its rules live in `review.css`, not `dashboard.css`, so there was nothing to split out.

Tests that read a rule read every stylesheet (`tests/web/stylesheets.ts`, in main.tsx's order); the guard reads every page stylesheet.
