# Terminal appearance (theme, font, size, line height)

Every terminal in work web (a session's, the Ctrl+K assistant's, an account's sign-in: all `PtyView`) draws with one style, set on the Settings page's Terminal section and kept in config.json: `terminal.theme` (Default dark, Midnight, Dracula, Tokyo Night, GitHub Light), `terminal.fontFamily` (a font installed on the computer: work ships none), `terminal.fontSize` (8–32, default 13) and `terminal.lineHeight` (1–2, default 1). `terminal.colors` (hand-written in config.json only, listed in `SETTINGS_ELSEWHERE`) changes single colours over the theme, by xterm's `ITheme` names (`background`, `foreground`, `cursor`, `cursorAccent`, `selectionBackground`, the 16 ANSI colours `black` … `brightWhite`), each `#rgb` or `#rrggbb` — `#rrggbbaa` for `selectionBackground` only (xterm draws the others opaque, and a see-through background would leave the terminal's frame see-through over the page). With nothing set the terminal looks as it did before themes: Default dark is today's `#1e1e1e` / `#d4d4d4` with xterm's own Tango colours, and the font is today's Cascadia stack.

`core/settings/terminal-style.ts` (pure, imports nothing, shared with the SPA: `SPA_SHARED`) holds the themes' full palettes and `resolveTerminalStyle(values, colors)`, which turns the Settings page's values (by path, as `SettingsWire.values` has them) into what xterm takes, field by field: one that doesn't fit is its default, the others stand. The user's fonts go first, each name trimmed and put in quotes of its own (`fontList`: a stray quote, `"Hack`, would otherwise void the whole CSS list, today's stack with it; a generic family like `monospace` stays bare), and today's stack after them, so a name that isn't installed falls back. `readSettings` (`settings-admin.ts`) sends the colours as `SettingsWire.terminalColors`, only the ones `checkTerminalColors` keeps and only when one does; nothing else of `terminal.colors` leaves config.json. `loadConfig` reads `terminal` too (`TerminalConfig`: its fields by type, the colours that fit), though work web never reads it from there: `saveConfig` writes the typed config, so a command that saves config.json (`work config remove-repo`, `add-group`, `remove-group`, `work init`) would otherwise drop it — and a colour that doesn't fit is dropped by such a save, as other hand-written keys are. § WHEN adding a key the Settings page writes, read it in `loadConfig` for the same reason. The schema can't import the theme module (it is import-free), so the font's pattern is written twice (`TERMINAL_FONT_PATTERN`, `SETTING_PATTERNS.fontFamily`) and a test holds them equal.

In the SPA, `state/terminal-style.ts` is the one style the page's terminals share. `DashboardApp` holds the page's one subscription (`useTerminalStyleUpdates`; one per terminal would read twice per change): it asks for the style as the page starts, so it is in before a terminal's first replay and the terminal is fitted once, at the user's size (until then, and if the read fails, it is today's look; a failed read is asked again by the next terminal to mount), and again on `settings-changed` and when the event stream (re)connects (a change sent while it was down, or a first read that failed while the server started). One read at a time, and its subscribers are told only when the style really changed (an unrelated setting refits nothing). It sets `--term-bg` / `--term-fg` on `<html>` (defaults in `tokens.css`), which the terminal's surroundings paint with (the pty host and its viewport, the Connecting… cover, the start-failure cover, the assistant's body, the deck's slot, the sign-in box), so a light theme has no dark frame; the covers' text is a `color-mix` with `--term-fg` that is exactly the old colour on the default theme. § A style change never reconnects: `PtyView` builds its Terminal from the style it has, and a later change sets xterm's options on the open terminal, refits, and resizes the PTY only when its columns or rows changed — as a window resize does (the client used last sets the PTY's size, pty-host.md); the connect effect does not depend on the style. A terminal hidden in the deck sends nothing and refits when shown.

Claude Code draws with its own colours, picked by its `/theme`, inside whatever background the terminal has: on GitHub Light, switch Claude Code to a light theme too (the Theme setting's help says so).
