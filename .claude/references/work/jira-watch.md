# Jira watch (newly assigned issues start themselves)

Off until you turn it on on Start ("Start newly assigned Jira issues by themselves"; `PUT /api/jira/watch`). Turning it on records the issues assigned to you then — all of them, `fetchMyIssuesOrThrow`, not the Jira tab's 50 — as `baseline`, so only ones assigned afterwards are acted on, and it refuses to turn on when `acli` can't list them (it couldn't tell new from backlog). Every 5 min (full `work web`, `server/routes/jira-watch-routes.ts`), for each new issue: `fetchIssueDetail` (project, components, labels, the description as text — `adfText`), then the summarising agent (`runInternal`: no tools; the issue is someone else's words) gets `choicePrompt` — your repos and groups (`watchTargets`: a README line or package description each) and where earlier issues of the same Jira project were worked (`projectHistory`, from sessions' Jira keys and branch names) — and answers JSON. `parseChoice`: only a sure answer naming one of your projects starts it; anything else is a suggestion. Sure: `setupWorktree(target, feat/<KEY>, …, {name})` and the session's Claude started with `jiraPrompt(issue, {automatic: true})` (shared with Start's Jira rows, `core/jira/jira-prompt.ts`; it asks Claude to raise DECISION NEEDED if the issue doesn't belong there), in normal permission mode like every host session. Unsure, or a start that failed: the issue's row on Start shows it with a project picker, "Start in <project>" and Dismiss (`POST /api/jira/watch/:key/start|dismiss`). At most 2 starts a check and `jiraWatch.maxPerDay` (default 5) a day; the rest wait undecided. It lists issues with `fetchMyIssuesOrThrow` (all of them, `--paginate`; acli down is a failed sweep, never "none"), and when the list's query changes what it shows (`LIST_VERSION`, now 2: open by status category, `MY_ISSUES_JQL`) the first sweep after takes the issues it hadn't seen as there (`adoptListChange`), so a newly visible backlog doesn't start itself. One decision per issue in state.db `jira_watch` (schema v4), the switch in `meta`; each decision is noted in the Activity panel (`jira-watch`). Start lists the issues in workflow order by Jira's status category (`core/jira/jira-board.ts`).
