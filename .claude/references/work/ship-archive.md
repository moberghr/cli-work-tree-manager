# Ship & archive

`Ship` runs `core/pr/ship.ts` per repo. **Groups ship in parts**: backend may be merged while frontend is in review.
- A repo is **done** when its PR is MERGED or it was never touched (0 commits vs `origin/HEAD`, clean, no PR). Done repos are never blockers and never selectable.
- "Published" means `origin/<branch>` exists — not `@{u}` (`work tree` leaves new branches tracking `origin/main`); ahead/behind are measured against `origin/<branch>`, and push uses `-u origin <branch>` unless tracking already points there.
- **Merge = `mergeSelected`**: the client sends `repos: [{name, headSha}]` — the repos the user ticked and the PR heads it SHOWED. The server re-runs the preflight and refuses the whole call if any selected repo is unknown, done, blocked, or its PR head moved; only then merges each with `gh pr merge N --<method> --match-head-commit <that sha>`, stopping at the first gh failure. Unselected repos are never touched.
- Blockers include: dirty tree, not pushed, unpushed commits, origin ahead of you, PR head ≠ local HEAD, draft, closed, conflicts, behind base, branch protection, failing/pending checks.
- The session is **archived only when the merge merged something AND every repo is done** afterwards — and never one you asked to keep after its PR merges (`keepAfterMerge`, see the PR watch).
- **Archive** (`archiveSession`, `core/archive/session-archive.ts` — the one path for the Archive button, Ship's merge, the PR watch and cleanup): first checks nothing is waiting (`archiveWaiting`: reply drafts to post, notes not yet delivered, a Claude working or waiting for an answer) — the button asks and can force it (409 `blocked` → confirm → `force: true`); cleanup waits. **Merged work decides it** (`{ merged: true }`: the PR watch's auto-archive and Ship's merge): drafts, undelivered notes and a finished turn's question for you don't hold it up, and only a Claude in the middle of a turn does (`turnInProgress`: working, or at a permission dialog mid-turn — a needs-input state entered after the last turn ended; stopping it would lose the pending tool call; tried again on the next sweep). Nothing is lost either way: those rows stay in state.db with the session (deleted only with it), so Restore shows the drafts and delivers the notes on its next turn, and `archive.json` lists them (`kept`: each draft's text, each note, the question), shown as "Also kept: …" on the archived session and in the Activity note. (In work web the worktree is removed in a child process — `removeWorktreeInChild`, `core/worktree/remove-child.ts`: `work remove --worktree-only -- <target> <branch>`, hidden, folders only, the session kept, answering `work-worktree-removed true|false`; `ArchiveDepsOptions.removeWorktree`, passed by ship-routes and the PR watch's archive — because `git worktree remove` is synchronous and held up every request for as long as the delete took (reported: 24 s, the PTY host read as not answering). A child that never answers counts as not removed, reported: the archive keeps the worktree. The CLI and clean-up remove in process.) Then it stops its Claude, its dev server and whatever else still runs from its folders (`stopRunningFrom`, `core/platform/running-from.ts`: a process whose program is in them — an executable, or an interpreter's script, like the `vite` a Claude started in the background, which held a file in `node_modules` so git removed the worktree only in part; never one that only names the folder, like an editor open on it, nor an editor's language server running the worktree's own copy (`isEditorHelper`: tsserver, `--useNodeIpc`, `--clientProcessId`…); said in the outcome) (and releases watchers) — and from there to the end nothing may start that Claude again: `ensurePty` refuses a session being archived or archived (`core/archive/archiving.ts`), since a Terminal tab still open on it reconnects and would start it (an archived session once kept a live Claude that way, restored after every host restart), records each repo's branch tip, copies every transcript to `~/.work/archive/<id>/transcripts` (Claude Code deletes old ones itself) with `archive.json` (prompts, PRs, last summary), saves its **uncommitted work** (`core/archive/archive-uncommitted.ts`: modified, deleted and new files — not git-ignored ones — snapshotted into a commit on HEAD through a temp index like checkpoints, kept by `refs/work/archive/<id>/<repo>/<time>` in the repo and written as a binary patch to `~/.work/archive/<id>/uncommitted/`; at most 50 MB, else the worktree stays), and removes the worktree **only when cleanup's check says nothing would be lost** (merged, uncommitted files saved; commits not in the main branch still keep it; never a repo's own checkout). Its **git-ignored files that aren't build output** — local settings (`appsettings.Development.json`, `.env.local`), the editor's state (`.vs`, `.idea`) — are copied to `~/.work/archive/<id>/ignored/<repo>/` when the worktree goes (`core/archive/archive-ignored.ts`: async, smallest first, at most 5 MB a file, 50 MB a repo and 5,000 files looked at; environments and package caches — `.venv`, `packages` — left out like build output; only folders `git check-ignore` confirms are walked; `ArchiveRecord.ignored`), and Restore puts them back over the new checkout (`restoreArchivedIgnored`, once per repo, recorded even when one fails). They can hold secrets: `work move export` leaves them behind and retention deletes them after `archive.compressAfterDays` (`ignoredDroppedAt`). A kept worktree drops its save, since the changes are still there. **Removed only in part** (`core/worktree/leftover.ts`): `git worktree remove` deletes the files and stops at one in use (Visual Studio's), having dropped the `.git` link and the registration — a folder with no git (`isLeftover`). The archive counts that removed (`halfRemoved`, `ArchiveRecord.leftovers`) and keeps the save; Restore treats a folder with no `.git` as gone (`isWorktreeFolder`, not `existsSync`); before making it again, Restore looks for what still runs from that folder and refuses naming it (409 `holders`; the dashboard asks "Stop it and restore?" and sends `stopHolders`), and a creation that fails with the folder in use names what has it open (an editor: yours to close), and `createSingleWorktree` sets it aside (`<folder>.leftover-<time>`, refused with "close what holds it" while a file is in use), adds the worktree, and `setupWorktree` copies its files back after the save (`putLeftoverBack`: over a clean checkout, else only where nothing is; build output left out), then deletes it; a creation that fails puts it back where it was. Over the checkout only while the branch is at the archive's recorded tip: on a branch that moved since, it fills in only what's missing. A group where one repo is half-removed and another kept whole is kept (and keeps its saves). The dashboard shows such a folder as "not a git checkout any more" (`onOtherBranch[].noGit`). Removed: its checkpoint refs stay (deleted with the session, `clearSessionCheckpoints`: Restore puts the worktree back at the same path, so the Diff tab's turns come back), and a local branch already merged into the main branch is deleted (`branchesDeleted`; a squash-merged one stays — nothing else reaches its commits). Kept: the reason is recorded and its git-ignored build output is cleared. Afterwards an internal `claude -p` writes a few sentences on what was done (`summary.written`, `archive-summary.ts`), which the Sessions list shows and the conversation search finds. **Restore** (`work tree` into it, or Restore): `setupWorktree` first recreates a deleted branch at its recorded tip (`recreateArchivedBranches`), then the worktree, and `restoreArchivedTranscripts` puts the conversation back where Claude looks, so it continues. `restoreArchivedUncommitted` (`core/archive/archive-restore.ts`) then applies the saved patch to the new worktree, unstaged, once: it refuses a worktree that already has changes or a patch that no longer applies (the branch moved on), records why, and never tries again, so a later `work tree` can't bring old changes back over newer work; the ref and patch stay for doing it by hand. An archived session shows "· N changes saved" (`SessionArchiveInfo.savedUncommitted`). Deleting the session deletes its refs (`clearSessionCheckpoints` → `dropSessionSaves`). **Retention** (`archive-retention.ts`, daily, in the Activity panel): transcripts of archives older than `archive.compressAfterDays` (default 30) are gzipped — lossless, search and Restore read `.gz` (`readArchivedTranscript`); `archive.dropTranscriptsAfterDays` (default 0 = never) deletes them, keeping the summary. The archive folder goes with the session on delete (`sessionStatePaths`).

§ Restore means "as if it had never been archived": the branch (recreated at its tip), the worktree at its path, the branch it had checked out, uncommitted and untracked files, git-ignored local settings and editor state, the turns, the conversation — `tests/core/archive/restore-roundtrip.test.ts` archives and restores a real session and compares. WHEN archiving drops something new, put it back on Restore and add it there. A Restore that can't make the worktree answers why (500 with the reason), never "unknown session" — and the dashboard shows that reason where you clicked: the session header's note line (beside its Restore, which also says ⚠), under a conversation result's Restore, in the rail menu's toast.

§ WHEN adding a ship action, route git/gh through `CommandRunner` (argv, no shell) and re-check preconditions server-side — the client's preflight may be stale.
