# Updates and release notes

`core/updates/`: `updates.ts` (pure, shared with the SPA and the demo: `compareVersions`, `parseReleases` — published releases with a version tag, newest first —, `availableUpdate`, `whatsNewFor`, `installKindOf`) and `update-source.ts` (the I/O: `fetchReleases` — GitHub's releases API anonymously, `gh api` when that's refused —, the desktop app's two files, the version whose notes you saw in state.db `meta` `ui:seen-version`, and `createUpdates`, one per work web). work web reads the list 30 s after start and every 6 h (`lookForUpdates`, Activity kind `updates`) and watches `desktop-update.json`; a change broadcasts `updates-changed`. Routes (`app-update-routes.ts`): `GET /api/updates` (`UpdateWire`: running, install `desktop` | `npm` | `dev`, latest, the desktop app's state, `available`, `whatsNew`), `POST …/check` (the list again, and the app's updater), `POST …/restart` (409 without a downloaded update), `GET …/notes`, `POST …/seen`. The dashboard (`useUpdates`): `UpdateStrip`, a small card bottom right only when there's an update — the app has it (Restart), is downloading it, or the command for an npm install / a git checkout (Copy) —, Later per version (localStorage); the version on the top bar, a button (`HelpMenu`, as bearing's Help menu: which work runs and where an update stands — `updateStatus` —, Restart to update, Check for updates with how it went, What's new, Keyboard shortcuts; a dot on the button while an update is there; a yellow ⚠ in it when the app and the work web its window shows are different versions — `versionMismatch`, the app's own version against the server's `running`, with the why and the fix (quit and reopen the app: it replaces another version's work web on start) in its tooltip and menu), one click from anywhere; `WhatsNew`, every release's notes (the GitHub Release text, Markdown) newest first, opening by itself once after an upgrade on that version and then marked seen (a first install isn't shown it: `whatsNewFor`). § The notes are the GitHub Release's text: write them when publishing a release.
