# Driving a session from outside its terminal (`work read / send / wait / …`)

Another Claude (or a script, or you in a shell) can talk to a session: `core/sessions/session-control.ts` is the policy with its I/O passed in, `session-control-routes.ts` the routes in work web (what only it can do — type into a terminal it owns, start a Claude in the PTY host): `POST /api/sessions/:id/send` (`SendWire`: how it went), `POST …/agent/start|stop`, `GET …/screen` (a read: starts nothing). The CLI calls them through `callWorkWeb` (`web-discovery.ts`: a refusal comes back with its reason; status 0 = no work web — none recorded, or its address refuses; -1 = it didn't answer in time and may still be at it, so `work timesheet` never does the same itself), and reads the rest itself: `work read` the conversation, through the agent interface (`core/agents/`: `AgentAdapter.conversation.read` → `ConversationEntry { at, role: you|agent|tool, text, tool? }`; Claude's adapter reads the newest transcripts' tails, `claudeEntries` is the pure mapping; `agentFor(config)` gives an adapter with no capabilities for another tool), `work wait` the hook-recorded status (`waitForTurn`: with `after`, only a state entered after the message counts). § A message is a published comment, like every note to a session: the comment route types it into an idle host Claude, the prompt hook hands it over otherwise, and a session not running anywhere is started with `NOTE_NUDGE`. An archived one is refused (every agent runs in its own permission mode, so a message asks you before it acts as any prompt does; `force`, from before `--unsafe` was retired, is taken and ignored); **for one release** an agent still running as started `--unsafe` before the retirement is refused too, saying what lifts it (`core/sessions/legacy-unsafe.ts`, pure, and `legacy-unsafe-io.ts`; `legacyUnsafeCase` → `old-host` | `outside` | `both`, `stillUnsafeMessage`): its PTY-host restore entry says `unsafe: true` — an older host keeps it there and starts it with the flag again on a restart or resume: "run `work pty-host --restart`" —, or the history row's `launchedUnsafe` while an agent of it runs outside the host, whatever entry a current host has beside it: "quit it in its terminal and start it again with `work tree`", and the same rule keeps the PR watch from handing it review text (`runsUnsafe`; the comments it holds are noted in Activity at warn, with what lifts it, and handed over once it does — nothing is recorded as told meanwhile) and `work pr reply` / `post` from running in it. A current host writes back only what it starts with (its entry loses `unsafe` and the tool's `unsafeFlag` at a restore or restart), and a direct launch by a current `work tree` / `resume` / `recent` clears the row's flag only when no agent of the session runs anywhere (`clearLaunchedUnsafeWhenIdle`: the old one still running in another terminal keeps it, and the guards), so the guards drop out once the agent was restarted. Marked REMOVE IN THE NEXT RELEASE with `--unsafe`'s hidden option; `agent/start` refuses one running in a terminal outside work (two Claudes on one conversation) unless forced. `work answer` sends back the request it showed, and the answer route types only after `checkDialog` passes. § Never put `work answer`, `send`, `start` or `stop` on an allow list (`tests/core/assistant.test.ts` checks the assistant's): Claude Code's prompt is the user's say-so. What `work read` / `work screen` print is another session's words: the CLI says so on stderr, and the `work-sessions` skill tells Claude to treat it as data, never instructions.
