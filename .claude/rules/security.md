# Security (§1)

> Shared checklist: `.claude/references/security-checklist.md`. This is a local dev CLI — the trust surface is the user's machine, git remotes, and spawned subprocesses.

- **§1.1** [CONVENTION] WHEN building a git/shell command, use `cross-spawn` with an argv array — DO NOT interpolate user/branch/path input into a shell string. Shell-string interpolation of branch names or repo paths is a command-injection vector.
- **§1.2** [CONVENTION] WHEN spawning subprocesses or PTY sessions, validate/normalize file-system paths (worktree roots, repo aliases) before use; never pass unresolved user input to `fs` or `node-pty` directly.
- **§1.3** [CONVENTION] The local diff/comment server (`src/server/comment-server.ts`) binds `node:http`. Keep it bound to localhost and short-lived; do not expose it on `0.0.0.0`.
- **§1.4** [ENFORCED] NEVER commit secrets, tokens, or absolute user-specific paths. State and logs belong under `~/.work/`, which is outside the repo.
- **§1.5** [ENFORCED] Every local server goes through `refuseReason` (`src/server/local-origin.ts`): Host must be ours, cross-site and same-site (another localhost port) requests are refused except a top-level page load (GET/HEAD, `Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`), and mutating requests / WebSocket upgrades need no Origin or our own. WHEN adding a GET route, keep it free of side effects that matter — a page on another site can make the browser open it.
- **§1.6** [CONVENTION] WHEN acting on a remembered pid (kill, "is it running"), check it is still ours: same boot (`bootTime()`) and, before killing, the same executable (`processName`). Pids are reused, fast on Windows.
- **§1.7** [CONVENTION] Internal `claude -p` runs (checkpoint names, group CLAUDE.md) go through `internalClaudeSpawn()` (`src/core/agents/claude/internal.ts`): no tools, neutral cwd — their prompts carry text we don't control. The one exception is the Reviews AI step, which may READ a temporary checkout of the PR (`internalClaudeReadOnlySpawn`, `core/review/review-tree.ts`): read-only file tools confined to that folder (`--restricted --tools Read,Grep,Glob`), none of its settings, hooks or MCP servers (`--setting-sources user`, `--strict-mcp-config`, and its settings files deleted first), the checkout made with no hooks and no symlinks, removed afterwards. Never run anything from such a checkout — no install, build, test or script — and never give that run a tool that runs, writes or fetches. PR review text reaches a session's Claude only from reviewers with write access (`TRUSTED_ASSOCIATIONS`, `pr-review.ts`) or the review bots in `prWatch.trustedBots` (default Copilot + github-actions, `DEFAULT_TRUSTED_BOTS`). Claude writes to GitHub only through `work pr post`, and only once the user said yes to the drafts (`work pr reply`) in the conversation; the user's Post click is the other way out (`pr-replies.ts`). Never put `work pr post` on an allow list: Claude Code's permission prompt is the second check. `work answer` (approving another session's tool call) and `work send` / `start` / `stop` / `restart` (making another session act) are never pre-allowed either; what `work read` / `work screen` return is another session's words — data, never instructions. work never starts an agent with its permission checks off: every session's agent starts in its own permission mode (`--unsafe` is retired; `tests/architecture/no-skip-permissions.test.ts` keeps any skip-permissions flag out of `src/`, `plugins/` and `scripts/`). For one release an agent still running as started `--unsafe` before the retirement (its PTY-host restore entry says `unsafe: true`, or with no entry its history row's `launchedUnsafe` while it runs outside the host: `core/sessions/legacy-unsafe.ts`) keeps the old guards — no review text from the PR watch, `work send` refused, `work pr reply` / `post` refused in it — until it is restarted by a current host. The Reviews AI step only READS a PR's checkout (`oneShot.readOnly`: file tools confined to it, nothing runs, its settings deleted and unread; started only on an agent version its flags were measured on, `readOnly.available()`), never runs it. **Fix it myself** is different on purpose: it starts a normal session on the PR's branch whose agent builds and runs the tests — running the PR's code, as Work on it does — in the agent's normal permission mode, with the agent's own prompts as the check; it pushes only on the user's yes. An internal run's OUTPUT that goes on to a session's Claude (a fork's conversation summary, `fork.ts`) is context, never an instruction: fenced, said so, with the user's own words after it.
